# 場邊 COURTSIDE｜籃球策略實驗室

以 2015 年 12 月 25 日 NBA 聖誕大戰的**克里夫蘭騎士（CLE）對金州勇士（GSW）**為背景。你可以重播實際比賽，也能當教練改變陣容或打法，看看同一局面在模型裡可能怎麼發展。這是回顧用的瀏覽器原型，不是賽事預測工具。

**[開啟線上預覽（需登入 Devin）](https://hs-basketball--bcvnzw2n.preview.devinapps.com/)**

## 功能

| 功能 | 可以做什麼 |
| --- | --- |
| 區段教練（預設） | 選騎士或勇士，設定五人陣容、節奏、防守、攻擊對位與暫停。先以八個教練區段推進，第四節與延長賽的最後兩分鐘改在本隊進攻、或落後時的防守回合停下。 |
| 逐回合 | 一次完整的球隊球權算一回合，不是每次傳球都停下。歷史路線在死球和第四節／延長賽最後五分鐘的各回合停下，可選進攻打法、時間策略或防守；符合規則時可叫暫停、換人。 |
| 歷史重播與假設分支 | 沿原路重播可得到騎士 83：89 勇士的實際終場比分；改用自訂策略會分岔到模擬，不再套用史實比分。可復原、儲存分支或切回已儲存的進度；存檔留在目前的瀏覽器。 |
| 推演與模型比較 | 「驗證本單」對照目前選擇、推薦和基準；可展開六組模型比較（現行／四要素／球員影響三種估值 × 現行／布朗運動兩種勝率）。配對蒙地卡羅推演呈現結果範圍，而不是保證勝率。 |
| SportVU、決策論點與賽後復盤 | 有追蹤資料的歷史回合可查看球員位置、持球與傳球細節，不會推進比賽。執行後可查看結果，終場可回看已執行的決策；正反論點由規則引擎提供，可選用 Claude 潤飾。 |

## 怎麼玩

1. 開啟預覽，在頁首選模式和本隊。第一次玩可點「新手教學」→「載入案例」；也可從「選擇起點與分支」挑一個比賽時刻。
2. 想看原本怎麼打，在區段教練模式選「沿歷史區段重播」後按「執行」。想試不同打法，選「執行教練策略・建立分支」，例如先把節奏改成「推進」，其他設定維持不變。
3. 先按「推演」，在「驗證本單」比較自己的方案和基準，再按「執行」推進到下一個停點。若想試另一種打法，可按「復原」或先儲存分支做對照。

## 資料來源：實際與估計

| 類型 | 來源與限制 |
| --- | --- |
| **實際比賽紀錄** | [NBA 逐球紀錄（場次 0021500438）](https://raw.githubusercontent.com/sealneaward/nba-movement-data/master/data/events/0021500438.csv)用於還原比分、球權與犯規等事件；[Basketball Reference 單場數據](https://www.basketball-reference.com/boxscores/201512250GSW.html)用於交叉核對，另採用 [CLE](https://www.basketball-reference.com/teams/CLE/2016.html)／[GSW](https://www.basketball-reference.com/teams/GSW/2016.html) 2015–16 球季統計及已公布的 BPM 作為模型輸入。 |
| **實際追蹤，推斷的持球與傳球** | [SportVU 追蹤資料](https://github.com/neilmj/BasketballData)只用於歷史回放；持球者與傳球由座標推斷，不是官方逐次標記。缺少追蹤的回合不補造資料。 |
| **模型估計** | 戰術得分分布不是兩隊的官方 Synergy 統計；勝率、陣容與對位效果、疲勞、推算的進攻時鐘與暫停額度，以及自訂分支的結果都屬估計。即使顯示的是歷史比分，比分旁的模型勝率仍是估計。模型使用完整比賽和球季統計，不能拿來當作當時可得的預測。 |

## 本機執行

需要 **Python 3.10+**；遊玩不必安裝套件、建置前端或下載原始資料。

```sh
git clone https://github.com/e76541yamo-maker/HS_Basketball.git
cd HS_Basketball
python3 server.py
```

在瀏覽器開啟 <http://localhost:3000>。若連接埠已被占用，可用 `PORT=3107 python3 server.py` 改用 3107。

不需 API 金鑰即可遊玩。若要啟用 Claude 潤飾，請只透過伺服器環境變數 `ANTHROPIC_API_KEY` 提供金鑰；未設定或服務失敗時會使用規則引擎的論點。

若要執行開發檢查，請在專案根目錄用 **Node.js 22+** 執行 `npm run check && npm test`。模型公式、逐球資料驗證、重建流程與授權見[技術筆記（英文）](docs/technical-notes.md)。
